- Страница 1536×1024 — утверждённый визуальный эталон для сравнения. Дополнительно проверять 1920 px и широкий горизонтальный viewport. В настоящем браузере свежие эталонные скриншоты в ходе этапа 1 **не сделаны**; при следующем визуальном QA нужно снять скриншоты текущего production/preview до мобильных изменений.

## Разделение в коде — решение для этапа 2
1. Desktop-компоненты и Desktop CSS сохраняются. Мобильные правила — в отдельном файле, подключаемом через mobile-only `<link media="(max-width: 700px)" ...>` или эквивалентную область `@media`. 700 px — стартовый инженерный порог, корректируется по результатам проверки в браузере; ширина 402 px — эталон дизайна.
2. Только внутри mobile media query отменить Desktop `min-width:1080px`, вынести мобильные размеры и позиционирование в scoped классы. Любое изменение shared-компонента должно быть не визуальным для Desktop или сопровождаться проверкой эквивалентности HTML/поведения.
3. Предпочитать общие семантические элементы и один источник данных; дополнительные мобильные DOM-элементы допускаются только для действительно независимого декора/управления и с корректными aria/hidden. Не допускать дублированных H1 и фальшивых ссылок в доступном/индексируемом дереве.
4. Мобильная главная сначала: header/menu/lang, hero, wave, About preview, latest-three D1 articles, footer. Весь сайт остаётся на тех же URL.
5. Проверки: 375/393/402/420/440 px; граница переключения ±1 px; Desktop минимум 1536 и 1920 px; RU/EN/FR; VoiceOver/keyboard/escape; no horizontal overflow; prefers-reduced-motion.
6. Публичный контент должен оставаться доступным без JS. Не менять административный редактор MacBook, бизнес-логику публикаций, R2 или статусы в рамках мобильного визуального этапа.
